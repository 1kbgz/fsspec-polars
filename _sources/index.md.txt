# fsspec-polars

Scan fsspec-db relations and SQL queries as Polars LazyFrames.

[![Build Status](https://github.com/1kbgz/fsspec-polars/actions/workflows/build.yaml/badge.svg?branch=main&event=push)](https://github.com/1kbgz/fsspec-polars/actions/workflows/build.yaml)
[![codecov](https://codecov.io/gh/1kbgz/fsspec-polars/branch/main/graph/badge.svg)](https://codecov.io/gh/1kbgz/fsspec-polars)
[![License](https://img.shields.io/github/license/1kbgz/fsspec-polars)](https://github.com/1kbgz/fsspec-polars)
[![PyPI](https://img.shields.io/pypi/v/fsspec-polars.svg)](https://pypi.python.org/pypi/fsspec-polars)

`fsspec-polars` registers Polars I/O sources backed by `fsspec-db`. Scans translate
supported projection, predicate, and row-limit hints into database requests and
apply remaining work locally.

## Documentation

[Query a SQLite table with Polars](docs/tutorial.md) creates its own database and
runs a complete scan. [Scan relations and SQL](docs/how-to-scan.md) covers existing
filesystems, explicit schemas, and optional SQL pushdown.

The [scan reference](docs/reference.md) describes both public functions. Read
[Query pushdown and materialization](docs/explanation.md) for execution costs and
fallback behavior.
