.. py:function:: scan_kafka(path: str, *, storage_options: collections.abc.Mapping[str, Any] | None = None, filesystem: Any | None = None) -> polars.LazyFrame

   Scan a Kafka topic, or one partition, from fsspec-kafka as a Polars LazyFrame.

   Filters on ``partition``, ``offset``, and ``timestamp`` choose which partitions and
   offsets are read. Row limits stop reading further partitions, but each partition is
   read whole, because compaction leaves gaps between offsets. Every filter is also applied to the rows read, so filters that cannot
   narrow the read still apply. Pushdown needs the ``pushdown`` extra.


.. py:function:: scan_path(path: str | os.PathLike[str], *, storage_options: collections.abc.Mapping[str, Any] | None = None) -> polars.LazyFrame

   Scan the table behind ``path`` as a Polars LazyFrame.

   ``path`` is a local path, which may be on an fsspec-fuse mount, or an fsspec URL such as
   ``dataview://main/orders.parquet::db+sqlite:///shop.db``. Paths rendered by a data view
   resolve to the node they come from, so a scan of a mounted ``orders.parquet`` reads the
   database relation instead of the file. Database relations take projection, predicate,
   and row-limit pushdown through ``scan_db_relation``. Other sources read only the columns
   the scan needs and apply the row limit when there is no predicate; the predicate runs
   locally.
